Every feature, one page.

The short version first; the whole machine below.

  • Pipelined NNTP at line rate — 8.31 Gbps measured on 10 GbE.
  • One-pass pipeline — decode, verify and extract overlap; RAR volumes never touch disk.
  • Multi-provider union availability — complete from the union of your servers, or abort early.
  • Memory budget — bounded RAM, graceful spill, never swaps.
  • Crash-safe resume — article-level journal; kill −9 mid-job and it picks up where it left off.
  • SABnzbd-compatible + NZBGet JSON-RPC APIs — Sonarr/Radarr/nzb360/LunaSea work unmodified.
  • Built-in indexer — scan groups into a local, searchable, Newznab-serving index.
  • Poster wall — artwork, ratings, cast, episode grids; no API keys.
  • Watchlist auto-grab + quality upgrades — grab on first appearance, upgrade to target quality.
  • Single self-contained executable — par2 + RAR unpack embedded.

Engine & speed

  • Pipelined NNTP — multiple requests in flight per connection defeats both round-trip latency and TCP congestion-window decay; measured +12%…+270% vs serial. Saturates lines with ~8 connections per server.
  • SIMD yEnc decode (rapidyenc, NEON/AVX kernels) — 4.95 GB/s per core, decoded in place in the receive path.
  • Multi-server shared queue — providers self-balance within ~2%, no tuning; per-server rate awareness with tail duplicate-dispatch so one slow server can't drag a job's tail.
  • Cross-job soak — the tail of job N overlaps the start of job N+1: the line stays lit edge-to-edge across a queue (2% idle vs SABnzbd's 61% dark in the bench).
  • Slow-job watchdog — a download crawling on one slow server while others wait is auto-deferred to the back of the queue (progress kept) and resumed when the queue clears.
  • Idle-server prefetch — servers the active job can't use (its articles aren't on them) start the next queued job instead of idling.
  • Connection-tuning ladder — measures each provider's actual throughput knee (asked vs granted connections) instead of guessing.
  • Auto-speed governor — optional LEDBAT-style RTT governor yields to your household's traffic while using the rest of the line.
  • Speed limits & weekly scheduler — live-adjustable caps, local-time (DST-safe) schedule, "pause for N minutes" with auto-resume.
  • Memory budget — one global RAM budget (auto: RAM/4, capped; overridable). When the budget gets tight it shrinks buffers, then spills to disk and reads back once the job settles — it never swaps. A 190 GB job completes inside a 1 GB budget (~1.1 GB peak RSS); a 2 GB NAS profile is measured and documented.
  • Backpressure — a slow disk throttles the sockets rather than filling RAM (holds within ±1% of a write cap, with RAM falling under pressure).
  • Post-job memory trim — the daemon hands freed memory back to the OS when idle (footprint drops to ~8 MB between jobs on macOS).

The one-pass pipeline

  • Write once — decoded articles are pwritten at their final file offsets. No temp files, no assembly pass.
  • In-stream PAR2 verification — every block MD5-hashed from the decode buffers as it arrives; verification finishes when the download does. Stronger than the competitors' quick-check, and free.
  • Direct extraction — store-mode RAR posts (most scene releases) are mapped and extracted during download; the volumes never exist on disk. Disk writes = content × 1.0, disk needed = 1× (others need ~2×).
  • Deobfuscation — obfuscated posts are renamed from PAR2 metadata; ROT13-obfuscated names get rescued; hash-named junk is classified and gated.
  • Exact-fit repair — damaged blocks are known live; the minimum-byte set of recovery volumes is fetched during the download (knapsack-solved), and repair touches only damaged spans.
  • Compressed/encrypted fallback — non-store posts materialise and unpack via the native RAR engine, overlapped with the queue; encrypted sets park with a clear message.
  • Password handling — passwords from the *arr API, {{pw}} filename convention, or NZB metadata; a 🔑 unlock on the dashboard handles the rest (background unlock, then normal filing).
  • Safety rails — repaired source volumes are write-protected during re-extraction; exit codes only say "success" when the end state is actually usable.

Reliability & availability

  • Pre-flight availability check — pipelined STAT sweeps build a per-article × per-server matrix in seconds: COMPLETE / REPAIRABLE / IMPOSSIBLE before you've downloaded anything. Impossible posts abort having fetched almost nothing.
  • Union routing — an article is missing only when every live server refused it; articles route to servers that have them. Different backbones have different retention/takedown profiles — the union completes posts no single server can.
  • Crash-safe journal — article-level journal; kill −9 mid-job and it resumes, refetching only what wasn't persisted. Queue and history survive restarts.
  • Park + retry — failed jobs park to history; retry refetches only what's missing.
  • Chaos-tested — a mock NNTP server drives 10 end-to-end failure scenarios (430s, corruption, truncation, stalls, dead servers, kill −9) on every test run.
  • Provider reliability scoring — per-server completion rates tracked forever, surfaced in the dashboard (warn <98%).
  • Server diversity analyser — STAT-samples across your servers and clusters them by shared gaps: learn which of your providers are actually the same backbone before you pay for redundancy you don't have.
  • Quotas, block accounts & disk guard — daily/monthly quotas, lifetime byte budgets for block accounts (auto-excluded when exhausted), low-disk pause, per-provider daily usage history.
  • Dupe detection — dupekey/dupescore with alternative promotion: a failed grab automatically promotes the held alternative.
  • Retention-aware routing — old posts skip servers whose retention can't have them; unservable posts fail instantly instead of spinning.

Automation & integrations

  • SABnzbd-compatible API — the full surface the *arrs use: addfile/addurl, categories, priorities, pause/resume per job, retry, pagination, two-tier API keys. Sonarr/Radarr treat it as SABnzbd.
  • NZBGet JSON-RPC facade — nzb360, LunaSea and other NZBGet remotes work unmodified.
  • Newznab server — your local index answers t=search/tvsearch/movie: the *arrs can use your own scans as an indexer.
  • RSS auto-grab — feeds with an NZBGet-style filter language; add/edit live from the dashboard.
  • Watchlist — name shows/films (even unaired); per-episode tracking grabs each one on first appearance, upgrades quality until your target (e.g. 720p → 1080p REMUX), optionally deletes the superseded copy only after the upgrade verifies. Airdate calendar shows what's coming.
  • Watch folder — drop a .nzb, it downloads and the file disappears.
  • Smart folders — regex/keyword/size rules route downloads to categories at enqueue; optional TV filing renames to Show/Season NN/Show - S01E02.ext.
  • Cleanup rules — junk extensions deleted post-completion.
  • Post-processing scripts — SABnzbd's SAB_* env contract: your existing script ecosystem runs as-is.
  • One-click migration — imports servers from SABnzbd ini or NZBGet conf; reads sabnzbd.ini directly if that's all it finds.
  • Spotnet ingestion — spot signature verification and NZB synthesis, built in.

Indexer & the poster wall

Scan the groups you care about into a private index, then browse it as a poster wall. All metadata comes from keyless public sources fetched by your install — there is no API key to beg for.

  • Continuous group scanner — incremental OVER scans on your schedule, ~43k headers/s over fanned-out connections; date-bisected first scans (--max-age 2y skips years of headers in ~20 probes).
  • Ingest gates — kind/year/resolution/language/size filters keep indexer spam out of your database; obfuscated junk is detected and gated by default.
  • Scene-name parser — title/year/episode/quality/source from real-world stems, incl. date-coded dailies, multi-episode codes, ROT13-obfuscated names; releases dedupe into one card per title.
  • Instant search — search-as-you-type with quality filters and per-row watch buttons; quality badges everywhere.
  • Keyless enrichment — TVmaze (TV), iTunes Search (movies), public ratings datasets, Wikidata, Wikipedia and AniList fill in posters, ratings + vote counts, cast, genres and plots. Optional OMDb/TMDB keys supported but never required.
  • Episode grids — per-season chips, best encode per episode, one click to download; season packs marked; "watch series" per season header.
  • Trending rows — new-this-week and hot-right-now strips from post frequency.
  • Fix anything — wrong match? Pick from candidates or type the identity yourself; manual metadata is never overwritten. Poster by URL or upload. One button re-enriches a title; one wipes and rebuilds the whole index.

Preview & library

  • Preview before it finishes — ▶ Play hands your OS player an .m3u served by the daemon, so you can check a download is what you wanted without waiting for it to complete. Checking a point further in pulls the right articles to the front of the queue.
  • Library mode — instant *arr completion with .strm pointers; playing one triggers the real download at top priority with background re-verify.

Dashboard & settings

  • Live charts, no libraries — 1 s polling; throughput area, per-provider stacked area, verify-health timeline, queue burn-down, speed histogram; charts widen their time window with your browser window.
  • Resource monitor — CPU, RAM (vs budget), disk write and network on one chart, with a low-disk warning.
  • Provider leaderboard — servers re-sort by live performance; per-provider session bytes, connection counts, utilisation, reliability.
  • Queue management — drag to reorder, inline priority/category, per-download detail drawer, optimistic pause, "pause for N minutes".
  • Everything configurable in-browser — servers (with live connection tests), speed/schedule, connections/window/decoders, disk/quota, watch/scripts, indexing gates, library, RSS, security with key rotation. Settings persist across restarts.
  • Diagnostics built in — in-UI log viewer, system benchmark (network/compute/disk ceilings + advice), server-diversity analyser, connection ladder.
  • Data usage — 14-day stacked per-provider bars, daily history, lifetime counters for block accounts.
  • Quality of life — drag-drop .nzb anywhere, desktop notifications, completion sounds, first-run wizard, serve --open.

Deployment

  • Single self-contained executable — par2 + RAR unpack are native code in the binary — nothing extracted on first use. No runtime, no installer.
  • macOS first-class — universal binary (Apple Silicon + Intel), native SwiftUI menu-bar app, launchd unit, Homebrew formula.
  • Windows — fully static x64 exe, runs on stock Windows 10/11; double-click launcher with guided setup.
  • Linux & Docker — hardened systemd unit; multi-stage Docker image with linuxserver-style PUID/PGID entrypoint; compose file included. All platforms →
  • Guided setup — nzbfast setup interactive wizard, or auto-detection of an existing SABnzbd/NZBGet config. First download in under two minutes.
