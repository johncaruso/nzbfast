    Indexing

    What it finds: posts that were uploaded under a real filename. The scan reads newsgroup headers, so something posted as Some.Film.2026.1080p.WEB-DL.x264-GROUP.part01.rar is recognised, filed under its title, and shown on the wall with a poster, cast and ratings.
    What it cannot find: posts with the name taken out. A large and growing share of Usenet is uploaded deliberately obfuscated: the subject is random (p5cbKvaDJ1Y0PW6DvKCIfztzZ), the filenames inside are random too, and it all goes into a catch-all group like alt.binaries.boneless. The real name exists only in an NZB the uploader publishes somewhere else, so it was never posted to Usenet at all and there is nothing on the wire for any scanner to read. This is not a gap we can close later: no competitor recovers those by scanning either.
    For scale, in our own measurements a full index of 14.8 million scanned posts yielded about 31,000 browsable releases. Roughly one in five hundred.
    Worth turning on if you follow particular newsgroups where people still post under real names, you want to see what your provider actually carries rather than what somebody else says it carries, you want to judge retention and completeness yourself, or you would simply rather not depend on anyone else's service.
    Why a commercial indexer is still recommended: an indexer is told what a release is by whoever uploaded it, so it can name the obfuscated posts that no scanner can. It also carries years of back catalogue, and it is what Sonarr and Radarr expect. Add your accounts under Search indexers just above: searches on the wall can then ask them and grab straight into the queue, with none of this switched on.
    With the switch off nothing is scanned, no headers are fetched, no metadata or artwork is looked up, and no availability sampling runs. The poster wall, Browse and the Sonarr/Radarr feed are hidden until you turn it back on. The watchlist stays as long as you have indexer accounts, because it can ask those instead.

    Spotnet spots

    What it finds: around 170 to 200 new spots a day. Most are Dutch or Belgian, with a steady minority of English scene releases. Every spot is checked against the signature of the person who posted it before it is stored, and one that does not check out is thrown away.
    What it is not: a replacement for an indexer account. It is a small feed with no back catalogue, so it holds what has been spotted recently rather than everything ever posted. Spots also only cover what somebody chose to announce.
    Roughly a third of spots are filed as adult by the people who posted them. Those are left out of Browse unless you tick Include adult there.
    Spots appear in Browse under their own Spots option, kept separate from your own index so it is always clear which is which. Downloading one fetches the NZB it points at and queues it like any other download.

    Database

    Deleting releases frees space inside the database file, but the file itself only gets smaller once it is compacted, and a compact waits for a moment when nothing is downloading or scanning. So the size above can sit still for a while after a cleanup. The size limit is measured against what is actually stored, not against the space waiting to be reclaimed.

    Remote access · phone & away-from-home

    No API key is set: anyone on your network can control nzbfast at these addresses. Set one in Security below.
    Point your phone's camera at a code, or type the address - same Wi-Fi works immediately. For access from anywhere, the painless answer is Tailscale (free, no router changes): install it on this machine and your phone, and a "works from anywhere" code appears above automatically. Remote-control apps work too: add nzbfast as a SABnzbd server (this address + your API key) or an NZBGet server (any username, API key as the password). Avoid raw port-forwarding - the dashboard is plain HTTP; if you must, always set an API key.

    nzbfast is running in a container, so it never replaces its own files: you
    move it forward by pulling a newer image. Your settings, queue and downloads live in the folders you
    mounted, and survive the swap.
    

    
    Update it now
    
    
    If you created it as a Project (Container Manager or Portainer):
    
    
      
      
    1. Container Manager → Project → nzbfast → Stop.
      2. 
      
    2. Build (this pulls the new image), then Start.
      3. 
    
    
    
    If you created it by searching the Registry and clicking Run: Registry →
    re-download the latest tag, then Container → stop nzbfast → Action → Reset.
    

    
    Keep it up to date by itself
    
    
    Add this service to your Project's compose file, alongside the nzbfast
    service, and it checks nightly at 04:00 for a newer image. Set the timezone to yours.
    
    
      watchtower:
    image: containrrr/watchtower
    container_name: nzbfast-watchtower
    restart: unless-stopped
    environment:
      - TZ=Europe/London
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    command: --cleanup --schedule "0 0 4 * * *" nzbfast
    
    
    
    
    Worth knowing before you paste it: this needs the Docker socket,
    and mounting /var/run/docker.sock gives that container root-equivalent control of the machine.
    If you would rather not, skip it and have your NAS run
    docker compose pull && docker compose up -d on a schedule instead. On Synology that is
    Control Panel → Task Scheduler → Create → Scheduled Task → User-defined script, run as root.
    
    
    One thing that catches people out: none of this moves a container
    that was created from a version tag such as :1.0.3. Both Watchtower and a manual re-pull fetch
    the tag the container was created with, so use :latest if you want updates to arrive.
    
    
    If it does not come back after updating, the container prints why it
    stopped and the reason is in its own log: Container Manager, then Container, nzbfast, Details, and the
    Log tab. Over SSH that is docker logs nzbfast. Nothing is lost while it is stopped, and
    deleting the container or your config folder will not help.
