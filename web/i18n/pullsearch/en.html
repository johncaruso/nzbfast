Search your indexer accounts

If you have an account at an NZB indexer site, nzbfast can search it from here and queue what you pick, instead of you going to the site, downloading an NZB and carrying it back. It speaks the standard indexer API that all of those sites offer, so there is nothing per-site to set up: NZBGeek, NZBFinder, DrunkenSlug, DOGnzb and the rest work the same way. A Prowlarr or NZBHydra2 instance is one entry as well, and brings every indexer behind it along with it.

Adding an account. Settings → Search indexers → + Add indexer. Fill in a name of your choosing, the site's API address (its ordinary web address is enough; a Prowlarr entry looks like http://host:9696/1/api) and the API key from your account page there, then Apply indexers. Test asks the site what it supports and shows what came back, which proves the address and the key in one click. A saved key is never shown again: the box says so, and leaving it blank keeps the key it already has.

Searching. Open 🎬 wall in the header and switch to the release list. The dropdown beside the search box decides where a search looks: This index, which is what this machine has scanned itself, Indexers, or Both. Your choice is remembered. Asking your accounts needs something typed in the box, because browsing them on an empty query would spend a day's allowance on a list nobody asked for. With the built-in indexer off, which is how nzbfast arrives, there are no posters to show and the page is exactly this: a search box, your accounts, and the results.

The results. One row per release, newest first, with its size, its age and how often that indexer's own users have grabbed it. A release several of your accounts carry appears once. Under Both, a copy your own index already holds wins and the outside one is dropped, because grabbing what you have already indexed costs you nothing. Download queues it at high priority: nzbfast fetches the NZB itself, and from there the job is like any other, with repair, extraction, categories and scripts all unchanged.

Asking about one title. Open a title's card on the wall and press ⌕ Search my indexers. For films this asks by IMDb number wherever the site accepts one, which is the difference between the film you meant and every release whose name happens to contain those words. nzbfast looks that number up itself, so the page never holds one. Sites that do not offer number matching are asked in plain words instead.

Your allowance. Indexer accounts are metered: so many searches and so many downloads a day, depending on your tier. Put those two numbers on the entry and nzbfast counts against them, starting fresh at midnight UTC. 0, the default, means unlimited, and it still counts. An account that has spent its allowance sits the search out while the others run, and a line above the results names the one that was skipped, so running out is never silent. A site that answers with a limit of its own, or asks us to slow down, is set aside for an hour.

Where your key goes. Only to the indexer it belongs to. Keys are kept on this machine, never handed to the browser - each result row carries a ticket good for half an hour instead of a link - and stripped out of the log and out of any error the site hands back, so a pasted error message cannot leak one. A download can only ever fetch a link one of your own searches returned.

These are the same accounts an nzblnk link falls back to when the local index does not recognise its header, and the ones the watchlist can ask about wanted items (§10).

Also search my indexer accounts for wanted items, at the foot of the watchlist card, lets it ask the accounts from Settings → Search indexers as well as your own index (§5). It starts off, because it is the one thing here that spends a metered account without you clicking anything. Switched on, each watched item asks about twice a day, and only about what it has not already found, under the same daily limits and with the same notes when an account is skipped. A candidate from an indexer is judged exactly like a local one, so quality floors, upgrades, season packs and duplicate handling all still apply, and a local copy wins any tie because it costs no allowance. With the built-in indexer off, this is what gives the watchlist something to work from at all.
